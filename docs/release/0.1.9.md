# 0.1.9 Release Record

This records the staged `0.1.9` patch release candidate after the published
`0.1.8` crate set. It is not a publication receipt. Do not treat this document
as evidence that `0.1.9` is on crates.io or tagged in git until an authorized
publish lane completes.

## Target Claim

The 0.1.9 release keeps the 0.1.x default claim:

```text
cargo-allow inventories syntax-visible source exceptions and checks them
against a policy ledger.
```

It additionally hardens the adoption-quality receipt path for gate consumers:
`review_due` counts, exit-2 error receipts, ledger parse ergonomics, and
receipt run provenance (`mode`, `enforcement`, `policy_config`, `tool_version`).

It must not claim new scanner features, macro-expanded analysis, proof execution,
or crates.io publication until those lanes complete with receipts.

## Release Scope

0.1.9 is a maintenance and adoption patch:

- Receipt fixes for gate consumers (`#1465`, `#1467`, `#1468`, `#1469`).
- Matcher lifecycle alignment so `check`, `list`, and `worklist` agree on
  `review_due` posture.
- Test hardening and module decomposition carried in the 0.1.9 lane stack.
- ripr `0.10.0` readiness validation and fixture alignment only.

## Non-Goals

- Do not add new scanner identity lanes in this patch.
- Do not publish to crates.io from this staging record alone.
- Do not tag `v0.1.9` without explicit release authorization.
- Do not claim spec-system promotion beyond the existing preview boundary.

## Release-Candidate Evidence

Pre-staging validation on branch `receipt-fixes-0.1.9` included:

```text
rtk cargo fmt --all --check
rtk cargo clippy --workspace --all-targets -- -D warnings
rtk cargo test --workspace
rtk cargo run -p cargo-allow -- check --mode no-new --format markdown --receipt target/cargo-allow/check.receipt.json --output target/cargo-allow/check.md
```

`cargo-semver-checks release --baseline-version 0.1.8` was not run: the
installed `cargo-semver-checks` binary on this host does not expose a `release`
subcommand.

## Version and Install Examples

Workspace package versions are bumped to `0.1.9`:

```text

Cargo.lock
```

Public install examples in this repository now pin the staged `0.1.9` candidate:

```bash
cargo install cargo-allow --version 0.1.9 --locked
```

## Remaining Publish Lane

- crates.io dry-run and publish receipts
- `v0.1.9` tag and GitHub Release
- installed-binary smoke on the published crate
- policy ledger updates for any retained exceptions introduced by the lane

## Known Limitations

The 0.1.9 candidate remains source-tree/source-syntax scoped by default. It
does not execute repository code, Cargo, rustc, Clippy, build scripts, proc
macros, ripr, unsafe-review, coverage, or network checks as part of the scan.

## Rollback

If a premature pin or doc promotion lands before publication, revert install
examples and release docs to `0.1.8` and keep the receipt fixes on `main`
through the normal PR path. Crates.io versions remain immutable once published.
