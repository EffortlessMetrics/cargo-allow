# 0.1.7 Preview Release Notes

This is a draft release-note record for a future `0.1.7` patch release after
the published `0.1.6` crate set.

No package version has been changed by this record. No crate has been packaged,
tagged, published, or verified on crates.io for `0.1.7` yet.

## Target Claim

The 0.1.7 release should keep the 0.1.x default claim:

```text
cargo-allow inventories syntax-visible source exceptions and checks them
against a policy ledger.
```

It may additionally say that cargo-allow includes an opt-in `spec-system`
preview profile for static source-tree graph validation. That profile validates
registered source-of-truth artifacts and their structural relationships without
changing default cargo-allow behavior.

It must not claim that the profile is stable, default-enabled, or proof
executing. It must not claim macro-expanded, type-aware, MIR-level,
build-aware, control-flow, data-flow, unsafe-proof, test-adequacy,
coverage-proof, release-readiness, or semantic-correctness behavior.

## Preview Scope

The preview release notes cover the spec-system PR sequence merged after
0.1.6:

- Source-of-truth stack docs, templates, proposal, spec, support-tier map,
  active goal manifest, implementation plan, closeout placeholder, and
  doc-artifact ledger.
- Internal spec-system config, doc-artifact ledger parsing, artifact file and
  ID validation, graph link validation, support-tier validation, and profile
  mode reporting.
- `check --profile spec-system`, `audit --profile spec-system`, `worklist
  --profile spec-system --format json`, `doctor --profile spec-system`, and
  `init --profile spec-system` preview command surfaces.
- `cargo-allow.spec-system.v1` JSON artifacts with source-tree graph inventory,
  findings, work items, readiness, claim boundary, and scanner limitations.
- Spec-system worklist repair items for broken source-of-truth graph structure.
- Advisory and shadow CI artifact upload, clean shadow burn-in evidence, and
  repo-local blocking-mode dogfood for selected objective structural finding
  classes.
- Reviewer and agent output polish that separates blocking-eligible structural
  posture from advisory lifecycle posture.
- First-hour adoption and CI guidance for this profile as one opt-in
  governance profile among possible future profiles.

## Blocking-Eligible Structural Classes

Blocking mode may fail commands for objective structural failures:

- malformed explicit profile config.
- missing or invalid doc-artifact ledger.
- duplicate artifact IDs.
- invalid artifact kind or status.
- missing registered artifact files.
- unreadable registered artifact files.
- registered artifact files missing their declared IDs.
- unknown linked artifact IDs.

Judgment-heavy lifecycle checks should remain advisory for this preview:

- stale active goals.
- missing closeouts.
- support-tier proof completeness.
- README or release claim coverage.

## Non-Goals

- Do not make spec-system part of default `cargo-allow check`.
- Do not promote the spec-system support-tier row beyond Advisory as part of
  release-note preparation.
- Do not run proof commands from cargo-allow's own scan.
- Do not call GitHub APIs or network services from the scanner.
- Do not invoke Cargo, rustc, Clippy, build scripts, proc macros, ripr,
  unsafe-review, coverage, or repository code from the scanner.
- Do not claim stable support-tier status for the spec-system profile.

Before a real `0.1.7` release, refresh these commands on the exact release
candidate commit:

```bash
rtk cargo fmt --all --check

rtk cargo test --workspace
rtk cargo run -p cargo-allow -- doctor --profile spec-system --format json --output target/cargo-allow/spec-system-doctor.json

rtk cargo run -p cargo-allow -- worklist --profile spec-system --format json --output target/cargo-allow/spec-system-worklist.json
rtk cargo run -p cargo-allow -- check --mode no-new --format markdown --receipt target/cargo-allow/check.receipt.json --output target/cargo-allow/check.md
```

publish checks for the workspace crate set. Do not publish from this draft
record alone.

## Claim Boundary

The spec-system profile is structural source-tree graph validation. It may parse
TOML and Markdown and inspect repository files. It may verify IDs, paths,
statuses, links, support-tier proof fields, active-goal references, and closeout
links.

It must not execute proof commands, call GitHub APIs, inspect external PR state,
run Cargo, rustc, Clippy, build scripts, proc macros, ripr, unsafe-review,
coverage, or network checks as part of the cargo-allow scan.

## Rollback

Before publication, rollback is a normal revert of the release-note commit or
any spec-system preview PRs that are not included in the release scope.

After publication, crates.io versions are immutable. If a published package is
wrong:

```bash
rtk cargo yank <crate> --version 0.1.7
```

Then prepare and publish a fixed patch release. Do not reuse `0.1.7` for
corrected contents.
