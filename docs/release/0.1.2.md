# 0.1.2 Release Record

This records the completed `0.1.2` patch release after the published `0.1.1`
crate set.

The release is irreversible now that packages are published. If a published
package is wrong, the rollback path is to yank the affected version and publish
a fixed patch release. Do not reuse `0.1.2` for corrected contents.

## Target Claim

The 0.1.2 release keeps the 0.1.x claim:

```text
cargo-allow inventories syntax-visible source exceptions and checks them
against a policy ledger.
```

It may also say that saved check receipts can carry the same source exception
inventory breakdown as JSON reports, while preserving the source-tree
claim-boundary and scanner limitations.

It must not claim macro-expanded, type-aware, MIR-level, build-aware,
control-flow, data-flow, unsafe-proof, test-adequacy, or coverage-proof
analysis.

## Release Scope

0.1.2 is a patch release for product hardening merged after 0.1.1:

- Check receipts may include optional `source_inventory` kind and kind.family
  breakdowns, so durable no-new evidence can carry both gate counts and the
  scanned source-exception inventory.
- The receipt schema, shared schema-fragment coverage, and schema docs describe
  that optional receipt field.
- The ledger docs and roadmap record the receipt inventory contract.

Non-goals for 0.1.2:

- No scanner, matcher, policy, migration, or evidence-validation semantic
  changes beyond the existing 0.1.1 behavior.
- No claim of build-aware, Cargo-metadata, Clippy, rustc, proc-macro, or
  proof-tool execution.
- No source-tree policy broadening to make release checks pass.
- No laundering generated `baseline_debt` into reviewed approval.
- No compatibility claim for external dogfood lanes that were not revalidated
  during this release turn.

## Preflight Evidence

The release was prepared and published from a clean `main` branch equal to
`origin/main`.

Pre-publish checks:

```text
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo run -p cargo-allow -- check --mode no-new --format markdown --receipt target/cargo-allow/check.receipt.json --output target/cargo-allow/check.md
cargo package --list --workspace
```

Observed no-new posture before publishing:

```text
59 matched, 0 new, 0 stale
536 source-tree inventory files scanned via git_tracked
```

The final installed 0.1.2 binary smoke test observed:

```text
cargo-allow 0.1.2
60 matched, 0 new, 0 stale
537 source-tree inventory files scanned via git_tracked
```

The count changed from the handoff note after the 0.1.2 release document and
its reviewed policy receipt were added during release prep.

## Version Bump

This release moved the workspace package version, internal workspace dependency
requirements, and lockfile package versions from `0.1.1` to `0.1.2`:

```text
Cargo.toml
Cargo.lock
```

Public install examples now pin the published `0.1.2` release:

```bash
cargo install cargo-allow --version 0.1.2 --locked
```


The installed binary reported `cargo-allow 0.1.2` and the installed-binary
no-new check passed.

## Rollback

Crates.io versions are immutable. If publication is wrong:

```bash

```

Then prepare and publish a patch release. Do not reuse `0.1.2` for corrected
contents.
