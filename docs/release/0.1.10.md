# 0.1.10 Release Record

This records the staged `0.1.10` patch release candidate after the published
`0.1.9` crate set. It is not a publication receipt. Do not treat this document
as evidence that `0.1.10` is on crates.io or tagged in git until an authorized
publish lane completes.

## Target Claim

The 0.1.10 release keeps the 0.1.x default claim:

```text
cargo-allow inventories syntax-visible source exceptions and checks them
against a policy ledger.
```

It carries post-0.1.9 test hardening, release-workflow automation, and receipt
issue closeouts without expanding scanner identity or migration surfaces.

It must not claim new scanner features, macro-expanded analysis, proof execution,
or crates.io publication until those lanes complete with receipts.

## Release Scope

0.1.10 is a maintenance patch:

- Post-0.1.9 test hardening for `diff --config` missing-policy error
  discriminators (`#1681`, `#1683`) and `add` load/validate/write error paths
  (`#1685`).
- Tag-triggered release workflow and release documentation (`#1684`).
- Receipt issue closeouts carried in the 0.1.10 lane stack.

## Non-Goals

- Do not add new scanner identity lanes in this patch.
- Do not publish to crates.io from this staging record alone.
- Do not tag `v0.1.10` without explicit release authorization.
- Do not claim spec-system promotion beyond the existing preview boundary.
- Do not treat this as a feature or migration release.

## Known Limitations

The 0.1.10 candidate remains source-tree/source-syntax scoped by default. It
does not execute repository code, Cargo, rustc, Clippy, build scripts, proc
macros, ripr, unsafe-review, coverage, or network checks as part of the scan.

## Rollback

If a premature pin or doc promotion lands before publication, revert install
examples and release docs to `0.1.9` and keep the maintenance fixes on `main`
through the normal PR path. Crates.io versions remain immutable once published.
