# 0.1.10 Release Record

This records the staged `0.1.10` patch release after the published `0.1.9`
crate set.

The release is irreversible once packages are published. If a published package
is wrong, the rollback path is to yank the affected version and publish a fixed
patch release. Do not reuse `0.1.10` for corrected contents.

## Target Claim

The 0.1.10 release keeps the 0.1.x default claim:

```text
cargo-allow inventories syntax-visible source exceptions and checks them
against a policy ledger.
```

It improves adoption trust, source-truth portability, release automation, and
scanner reliability for source-tree exception ledgers. It must not claim
macro-expanded analysis, type-aware analysis, MIR-level analysis, build-aware
analysis, control-flow or data-flow proof, proof-tool execution, or test
adequacy.

## Release Scope

0.1.10 is a maintenance and adoption-trust patch:

- Portable governance substrate and `.allow/` profile migration groundwork.
- Migration parity and import-adapter characterization for the `spec-system`
  preview path.
- Multi-ledger federation, mirror-divergence visibility, and ledger-coherence
  change-control foundations.
- Diff movement/posture classification and required-change-note enforcement.
- First-hour adoption docs, CI examples, and release automation hardening.
- Security, inventory, matcher, refresh, schema, report, CLI, and scanner
  regression fixes accumulated after 0.1.9.

## Non-Goals

- Do not cut `0.2.0`.
- Do not raise the Rust MSRV; Rust 1.95 remains a follow-up lane.
- Do not claim full import mode, external ripr migration, or release readiness
  for unrelated downstream repositories.
- Do not claim macro-expanded, type-aware, MIR-level, build-aware,
  control-flow, data-flow, unsafe-proof, test-adequacy, or coverage-proof
  behavior.

## Release-Candidate Evidence

The final pre-publish candidate is expected to be the release-prep merge commit
that bumps the workspace version to `0.1.10` and adds this release record.

Pre-publish candidate evidence should include:

```text
rtk cargo fmt --all --check
rtk cargo clippy --workspace --all-targets -- -D warnings
rtk cargo test --workspace
rtk cargo package --workspace --locked
rtk cargo run -p cargo-allow -- check --mode no-new --format markdown --receipt target/cargo-allow/check.receipt.json --output target/cargo-allow/check.md
rtk bash scripts/release-version-preflight.sh 0.1.10
```

## Known Limitations

The 0.1.10 release remains source-tree/source-syntax scoped by default. It does
not execute repository code, Cargo, rustc, Clippy, build scripts, proc macros,
ripr, unsafe-review, coverage, or network checks as part of the scan.

## Rollback

Crates.io versions are immutable. If publication is wrong:

```bash
rtk cargo yank <crate> --version 0.1.10
```

Then prepare and publish a fixed patch release. Do not reuse `0.1.10` for
corrected contents.
