# 0.1.3 Release Record

This records the completed `0.1.3` patch release after the published `0.1.2`
crate set.

The release is irreversible now that packages are published. If a published
package is wrong, the rollback path is to yank the affected version and publish
a fixed patch release. Do not reuse `0.1.3` for corrected contents.

## Target Claim

The 0.1.3 release keeps the 0.1.x claim:

```text
cargo-allow inventories syntax-visible source exceptions and checks them
against a policy ledger.
```

It may additionally say that PR posture diffing and evidence diagnostics are
better at distinguishing valid evidence strengthening, weak evidence requiring
review, invalid local evidence policy weakening, and broken local evidence
links.

It must not claim macro-expanded, type-aware, MIR-level, build-aware,
control-flow, data-flow, unsafe-proof, test-adequacy, or coverage-proof
analysis.

## Release Scope

0.1.3 is a patch release for product hardening merged after 0.1.2:

- Evidence diagnostics gained explicit categories, friendlier human labels, and
  clearer schema language separating machine `category` values from human
  display labels.
- List, worklist, report, receipt, diff, Markdown, and HTML artifacts expose
  evidence health counts for broken local evidence links and weak evidence
  references.
- Default worklists now include retained policy entries with empty evidence
  references, while `--missing-evidence` remains a focus filter for that queue.
- Worklist JSON and human output summarize queue item kinds so agents can see
  the work mix before parsing every row.
- Audit guidance now routes broken, weak, and missing evidence cleanup to the
  corresponding worklist queues.
- Diff posture now treats invalid local-file evidence additions as failures,
  weak evidence additions as review-required posture, and valid evidence
  additions as improvements.
- Diff posture handles missing base or explicit head policy more predictably,
  including missing base policy scans, policy additions without a base policy,
  and explicit head revisions with no policy.
- Kind filters and item-kind filters fail closed on unknown values while still
  accepting documented aliases where supported.
- Baseline proposal and policy validation reject padded source-tree scopes and
  invalid generated-baseline expiry windows instead of normalizing bad policy
  input.
- Source-snapshot audit coverage now verifies that invalid Rust without a
  package manifest still scans visible source syntax through filesystem
  fallback, without requiring Cargo metadata or a build.

Non-goals for 0.1.3:

- No new scanner, matcher, migration, or policy broadening to make checks pass.
- No claim of build-aware, Cargo-metadata, Clippy, rustc, proc-macro, or
  proof-tool execution.
- No laundering generated `baseline_debt` into reviewed approval.
- No compatibility claim for external dogfood lanes that were not revalidated
  during this release turn.

## Version Bump

This release moved the workspace package version, internal workspace dependency
requirements, and lockfile package versions from `0.1.2` to `0.1.3`:

```text
Cargo.toml
Cargo.lock
```

Public install examples now pin the published `0.1.3` release:

```bash
cargo install cargo-allow --version 0.1.3 --locked
```

## Rollback

Crates.io versions are immutable. If publication is wrong:

```bash

```

Then prepare and publish a patch release. Do not reuse `0.1.3` for corrected
contents.
