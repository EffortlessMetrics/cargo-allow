# 0.1.3 Release Prep

This is a release-prep record for a future `0.1.3` patch release. It records
the post-0.1.2 scope currently merged on `main`; it is not a publication record
and does not mean `0.1.3` has been versioned, tagged, packaged, or published.

If this release is published later, replace this prep note with the final
observed dry-run, publish, registry, installed-binary, and rollback evidence.

## Target Claim

The 0.1.3 patch should keep the 0.1.x claim:

```text
cargo-allow inventories syntax-visible source exceptions and checks them
against a policy ledger.
```

It may additionally say that PR posture diffing and evidence diagnostics are
better at distinguishing valid evidence strengthening, weak evidence requiring
review, invalid local evidence policy weakening, and broken local evidence
links.

It must not claim macro-expanded, type-aware, MIR-level, build-aware,
control-flow, data-flow, unsafe-proof, test-adequacy, or coverage-proof
analysis.

## Candidate Scope

This patch is a candidate for product hardening merged after the published
0.1.2 crate set:

- Evidence diagnostics gained explicit categories, friendlier human labels, and
  clearer schema language separating machine `category` values from human
  display labels.
- List, worklist, report, receipt, diff, Markdown, and HTML artifacts expose
  evidence health counts for broken local evidence links and weak evidence
  references.
- Diff posture now treats invalid local-file evidence additions as failures,
  weak evidence additions as review-required posture, and valid evidence
  additions as improvements.
- Diff posture handles missing base or explicit head policy more predictably,
  including missing base policy scans, policy additions without a base policy,
  and explicit head revisions with no policy.
- Kind filters and item-kind filters fail closed on unknown values while still
  accepting documented aliases where supported.
- Baseline proposal and policy validation reject padded source-tree scopes and
  invalid generated-baseline expiry windows instead of normalizing bad policy
  input.
- Source-snapshot audit coverage now verifies that invalid Rust without a
  package manifest still scans visible source syntax through filesystem
  fallback, without requiring Cargo metadata or a build.

Non-goals for 0.1.3:

- No new scanner, matcher, migration, or policy broadening to make checks pass.
- No claim of build-aware, Cargo-metadata, Clippy, rustc, proc-macro, or
  proof-tool execution.
- No laundering generated `baseline_debt` into reviewed approval.
- No compatibility claim for external dogfood lanes that are not revalidated
  during the actual release turn.

## Required Release Work

Before publication, a release PR still needs to:

1. Bump the workspace package version, internal workspace dependency
   requirements, lockfile package versions, and public install examples from
   `0.1.2` to `0.1.3`.
2. Run the full release preflight:

   ```text
   rtk cargo fmt --all --check
   rtk cargo clippy --workspace --all-targets -- -D warnings
   rtk cargo test --workspace
   rtk cargo run -p cargo-allow -- check --mode no-new --format markdown --receipt target/cargo-allow/check.receipt.json --output target/cargo-allow/check.md
   rtk cargo package --list --workspace
   ```

3. Run package dry-runs in dependency order:

   ```bash
   rtk cargo publish --dry-run -p <crate> --locked
   ```

4. Publish only after dry-runs pass, in dependency order:

   ```text
   1. allow-core
   2. allow-policy
   3. allow-inventory
   4. allow-files
   5. allow-rust
   6. allow-match
   7. allow-report
   8. allow-policy-legacy
   9. allow-diff
   10. cargo-allow
   ```

5. Verify registry visibility and the installed binary:

   ```bash
   rtk cargo search cargo-allow --limit 1
   rtk cargo install cargo-allow --version 0.1.3 --locked --root target/cargo-allow-install --force
   rtk .\target\cargo-allow-install\bin\cargo-allow.exe --version
   rtk .\target\cargo-allow-install\bin\cargo-allow.exe --help
   rtk .\target\cargo-allow-install\bin\cargo-allow.exe check --mode no-new --format markdown --receipt target/cargo-allow/check.receipt.json --output target/cargo-allow/check.md
   ```

## Rollback

Crates.io versions are immutable. If a future `0.1.3` publication is wrong:

```bash
rtk cargo yank <crate> --version 0.1.3
```

Then prepare and publish a fixed patch release. Do not reuse `0.1.3` for
corrected contents.
