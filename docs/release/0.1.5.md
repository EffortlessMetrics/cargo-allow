# 0.1.5 Release Record

This records the completed `0.1.5` patch release after the published `0.1.4`
crate set.

The release is irreversible now that packages are published. If a published
package is wrong, the rollback path is to yank the affected version and publish
a fixed patch release. Do not reuse `0.1.5` for corrected contents.

## Target Claim

The 0.1.5 release keeps the 0.1.x claim:

```text
cargo-allow inventories syntax-visible source exceptions and checks them
against a policy ledger.
```

It may additionally say that evidence-health repair queues now carry clearer
machine routing metadata across reports, receipts, doctor output, SARIF, audit
roadmaps, proposal follow-up queues, and migration summaries.

It must not claim macro-expanded, type-aware, MIR-level, build-aware,
control-flow, data-flow, unsafe-proof, test-adequacy, or coverage-proof
analysis.

## Release Scope

0.1.5 is a patch release for product hardening merged after 0.1.4:

- Audit remediation and evidence repair routing are centralized across report
  renderers.
- JSON reports, receipts, doctor output, SARIF properties, and migration
  summaries expose stable evidence-health repair queue metadata.
- Proposal summaries route generated baseline debt to follow-up work queues
  without laundering generated entries into reviewed approval.
- Migration summaries route broken local evidence links and weak evidence
  references through worklist commands.
- Migrated unsafe evidence gaps include an additional unsafe-scoped worklist
  command when `unsafe_count` is non-zero, so reviewers and agents can focus on
  retained unsafe exceptions first.

Non-goals for 0.1.5:

- No scanner, matcher, migration, or policy broadening to make checks pass.
- No claim of build-aware, Cargo-metadata, Clippy, rustc, proc-macro, or
  proof-tool execution.
- No laundering generated `baseline_debt` into reviewed approval.

## Known Limitations

The 0.1.5 release remains source-tree/source-syntax scoped. It does not claim
macro-expanded, type-aware, MIR-level, build-aware, control-flow, data-flow,
unsafe-proof, test-adequacy, or coverage-proof behavior.

## Rollback

Crates.io versions are immutable. If publication is wrong:

```bash
cargo yank <crate> --version 0.1.5
```

Then prepare and publish a patch release. Do not reuse `0.1.5` for corrected
contents.
