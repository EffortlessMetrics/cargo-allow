# 0.1.4 Release Candidate

This is a release-candidate record for a future `0.1.4` patch release. It
records the post-0.1.3 scope currently merged on `main`. This is not a
completed release record. It is not a publication record. `0.1.4` has not been
tagged or published.

The workspace package version and internal dependency requirements have been
staged at `0.1.4` for package dry-runs. Public install examples remain pinned
to the latest verified crates.io release until publication is observed.

If this release is published later, replace this candidate note with the final
observed publish, registry, installed-binary, and rollback evidence.

## Target Claim

The 0.1.4 release keeps the 0.1.x claim:

```text
cargo-allow inventories syntax-visible source exceptions and checks them
against a policy ledger.
```

It may additionally say that setup diagnostics, evidence-health repair queues,
stale-prune previews, and source-tree initialization flows are easier to route
from saved artifacts and human output.

It must not claim macro-expanded, type-aware, MIR-level, build-aware,
control-flow, data-flow, unsafe-proof, test-adequacy, or coverage-proof
analysis.

## Candidate Scope

0.1.4 is a patch candidate for product hardening merged after 0.1.3:

- Crate-level docs now keep the source-tree/no-code-execution claim boundary
  visible in published library packages.
- Human `explain` and worklist output make evidence diagnostics easier to scan
  and route without parsing JSON.
- Stale-prune output includes TOML removal previews, and stale worklist proof
  commands route through dry-run and JSON prune artifacts.
- Worklist proof commands now include ledger lookup shortcuts such as
  `list --allow-id`, durable allow-ID queues, and common shortcut queues for
  baseline debt, broad scope, broken evidence, and weak evidence.
- Doctor, audit, check, diff, HTML, and SARIF reports surface evidence-health
  repair queues for broken local evidence links and weak evidence references.
- Policy validation rejects padded reason text so reviewable rationale does not
  hide whitespace-only edits.
- `cargo-allow init --root <source-tree>` resolves relative config output from
  the diagnosed source-tree root.
- `cargo-allow doctor` suggests the root-aware standalone init command in human
  output and saved JSON when no policy config is found.

Non-goals for 0.1.4:

- No new scanner, matcher, migration, or policy broadening to make checks pass.
- No claim of build-aware, Cargo-metadata, Clippy, rustc, proc-macro, or
  proof-tool execution.
- No laundering generated `baseline_debt` into reviewed approval.
- No compatibility claim for external dogfood lanes that were not revalidated
  during this release turn.
- No public install example update until 0.1.4 registry visibility and
  installed-binary verification are observed.

## Required Publication Work

Before publication, the release still needs to:

1. Run the full release preflight:

   ```text
   rtk cargo fmt --all --check
   rtk cargo clippy --workspace --all-targets -- -D warnings
   rtk cargo test --workspace
   rtk cargo run -p cargo-allow -- check --mode no-new --format markdown --receipt target/cargo-allow/check.receipt.json --output target/cargo-allow/check.md
   rtk cargo package --list --workspace
   ```

2. Run package dry-runs in dependency order, immediately before publishing each
   crate after its internal predecessors are visible:

   ```bash
   rtk cargo publish --dry-run -p <crate> --locked
   ```

3. Publish only after dry-runs pass, in dependency order:

   ```text
   1. allow-core
   2. allow-policy
   3. allow-inventory
   4. allow-files
   5. allow-rust
   6. allow-match
   7. allow-report
   8. allow-policy-legacy
   9. allow-diff
   ```

4. Verify registry visibility and the installed binary:

   ```bash
   rtk cargo search cargo-allow --limit 1
   rtk cargo install cargo-allow --version 0.1.4 --locked --root target/cargo-allow-install --force
   rtk .\target\cargo-allow-install\bin\cargo-allow.exe --version
   rtk .\target\cargo-allow-install\bin\cargo-allow.exe --help
   rtk .\target\cargo-allow-install\bin\cargo-allow.exe check --mode no-new --format markdown --receipt target/cargo-allow/check.receipt.json --output target/cargo-allow/check.md
   ```

5. Update public install examples from `0.1.3` to `0.1.4` only after registry
   visibility and installed-binary verification pass.

## Rollback

Crates.io versions are immutable. If a future `0.1.4` publication is wrong:

```bash
rtk cargo yank <crate> --version 0.1.4
```

Then prepare and publish a patch release. Do not reuse `0.1.4` for corrected
contents.
