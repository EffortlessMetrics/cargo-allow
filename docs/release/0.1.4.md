# 0.1.4 Release Record

This records the completed `0.1.4` patch release after the published `0.1.3`
crate set.

The release is irreversible now that packages are published. If a published
package is wrong, the rollback path is to yank the affected version and publish
a fixed patch release. Do not reuse `0.1.4` for corrected contents.

## Target Claim

The 0.1.4 release keeps the 0.1.x claim:

```text
cargo-allow inventories syntax-visible source exceptions and checks them
against a policy ledger.
```

It may additionally say that setup diagnostics, evidence-health repair queues,
stale-prune previews, and source-tree initialization flows are easier to route
from saved artifacts and human output.

It must not claim macro-expanded, type-aware, MIR-level, build-aware,
control-flow, data-flow, unsafe-proof, test-adequacy, or coverage-proof
analysis.

## Release Scope

0.1.4 is a patch release for product hardening merged after 0.1.3:

- Crate-level docs now keep the source-tree/no-code-execution claim boundary
  visible in published library packages.
- The root README is now a concise product landing page, with first-run,
  how-to, crate responsibility, and crate-local README documentation routed to
  focused docs instead of duplicating product content across package pages.
- Package metadata now points each crate at its crate-local README, while the
  root README remains the product landing page.
- Human `explain` and worklist output make evidence diagnostics easier to scan
  and route without parsing JSON.
- Stale-prune output includes TOML removal previews, and stale worklist proof
  commands route through dry-run and JSON prune artifacts.
- Worklist proof commands now include ledger lookup shortcuts such as
  `list --allow-id`, durable allow-ID queues, and common shortcut queues for
  baseline debt, broad scope, broken evidence, and weak evidence.
- Migration summaries now expose more adoption-health context: evidence-bearing
  entry counts, lint-exception entry counts, and weak-evidence reference counts
  when legacy conversion preserves unstructured evidence that still needs
  review. They also identify unsafe-specific weak evidence references so
  migrated unsafe entries with TODO or unstructured evidence remain visible as
  stronger-evidence repair work.
- Repo-policy migration coverage now includes legacy Clippy exception and
  unsafe allowlist inputs in the combined migration path.
- Weak-evidence work items for unsafe exceptions now route humans and agents
  toward unsafe-specific evidence such as unsafe-review, boundary tests, specs,
  or equivalent review receipts.
- Doctor, audit, check, diff, HTML, and SARIF reports surface evidence-health
  repair queues for broken local evidence links and weak evidence references.
- Policy validation rejects padded reason text so reviewable rationale does not
  hide whitespace-only edits.
- PR posture documentation now explains policy weakening, lifecycle posture
  changes, and reviewer-facing Markdown summaries. The Markdown PR summary now
  separates policy failures from review-required policy changes and policy
  improvements. Human and Markdown diff output now group finding and policy
  posture details by reviewer action so reviewers can scan source-finding
  attention items, source-finding improvements, policy failures,
  review-required policy changes, and policy improvements without parsing JSON.
- The root README remains a concise product landing page: detailed
  `source_package` claim-boundary wording is routed to `docs/claim-boundaries.md`
  instead of expanding the landing page with implementation detail.
- The Rust source-syntax scanner now detects source-visible `cfg_attr`
  conditionals that apply `unsafe(...)`, `allow(...)`, or `expect(...)`
  attributes, while ignoring quoted documentation strings and custom attribute
  names such as `my_allow(...)`.
- Post-candidate scanner hardening now also records the source-visible identity
  needed to distinguish more findings structurally: unsafe attribute columns,
  multiple `cfg_attr` unsafe/lint attributes, spaced attribute tokens,
  multi-lint attributes, multiple index expressions on one line, index receiver
  identity, panic macro path identity, unsafe function symbols, and unsafe trait
  symbols.
- `cargo-allow init --root <source-tree>` resolves relative config output from
  the diagnosed source-tree root.
- `cargo-allow doctor` suggests the root-aware standalone init command in human
  output and saved JSON when no policy config is found.

Non-goals for 0.1.4:

- No new scanner, matcher, migration, or policy broadening to make checks pass.
- No claim of build-aware, Cargo-metadata, Clippy, rustc, proc-macro, or
  proof-tool execution.
- No laundering generated `baseline_debt` into reviewed approval.
- No compatibility claim for external dogfood lanes that were not revalidated
  during this release turn.

## Known Limitations

The 0.1.4 release remains source-tree/source-syntax scoped. It does not claim
macro-expanded, type-aware, MIR-level, build-aware, control-flow, data-flow,
unsafe-proof, test-adequacy, or coverage-proof behavior.

## Rollback

Crates.io versions are immutable. If publication is wrong:

```bash
cargo yank <crate> --version 0.1.4
```

Then prepare and publish a patch release. Do not reuse `0.1.4` for corrected
contents.
