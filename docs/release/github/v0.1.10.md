# cargo-allow v0.1.10

cargo-allow v0.1.10 is a maintenance patch focused on post-0.1.9 test hardening,
release-workflow automation, and receipt issue closeouts. It does not introduce
new scanner features or migration surfaces.

Default cargo-allow behavior remains the source-exception ledger:

```bash
cargo-allow audit
cargo-allow check --mode no-new
cargo-allow diff --base origin/main
cargo-allow worklist --format json
```

## Highlights

- Hardens `diff --config` missing-policy error discriminators (`#1681`, `#1683`).
- Hardens `add` load, validate, and write error paths (`#1685`).
- Adds tag-triggered release workflow and release documentation (`#1684`).
- Carries receipt issue closeouts without expanding scanner claim boundaries.

## Install

Staging pin used while the release lane is open:

```bash
cargo install cargo-allow --version 0.1.10 --locked
```

Do not treat this body as proof of crates.io publication until the authorized
publish lane completes.

## Claim Boundary

cargo-allow scans source-tree inventory without executing repository code. This
release improves test coverage and release automation; it does not add
macro-expanded, type-aware, MIR-level, build-aware, control-flow, data-flow,
unsafe-proof, test-adequacy, or coverage-proof behavior.
