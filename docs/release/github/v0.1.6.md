# cargo-allow v0.1.6

`cargo-allow` is a source-tree exception ledger for Rust repositories. It scans
repository files without executing project code, then checks syntax-visible
exceptions against `policy/allow.toml`.

This patch release hardens migration evidence preservation, source-syntax
identity, and no-new policy posture without expanding the claim boundary.

## Highlights

- Preserves recognized and unstructured evidence when migrating Clippy,
  no-panic, non-Rust, generated-file, executable-bit, workflow, dependency,
  process, and network legacy policy lanes.
- Honors root-relative evidence references while converting legacy `from`
  sources, so migrated entries remain traceable to their original evidence.
- Records more precise source-syntax identity for unsafe impls, unsafe extern
  blocks, unsafe item containers, unsafe attribute targets, trait-method
  containers, extern signatures, lint-attribute target scope, panic-family macro
  paths, nested panic receivers, index expressions, and string slicing.
- Keeps panic fixture policy aligned with the current scanner shape without
  weakening the no-new source-tree claim.
- Updates repository agent guidance to match the current PR, swarm, and release
  operating model.

## Validation

The release record includes preflight, publish, registry, install-smoke, and
source-tree no-new evidence. The completed release validation included:

```text
rtk cargo check --workspace
rtk cargo fmt --all --check
rtk cargo clippy --workspace --all-targets -- -D warnings
rtk cargo test --workspace
rtk cargo run -p cargo-allow -- check --mode no-new --format markdown --receipt target/cargo-allow/check.receipt.json --output target/cargo-allow/check.md
rtk cargo package --list --workspace --allow-dirty
rtk cargo install cargo-allow --version 0.1.6 --locked --root target/cargo-allow-install --force
```

The installed `cargo-allow 0.1.6` binary passed the no-new check with `78`
matched findings, `0` new findings, and `0` stale policy entries over `571`
git-tracked source-tree inventory files.

## Claim Boundary

`cargo-allow` scans source-tree inventory and source-syntax findings. It does
not execute repository code and does not require Cargo metadata, `cargo check`,
rustc, Clippy, build scripts, proc macro expansion, dependency resolution,
`cargo-deny`, `cargo-vet`, `ripr`, `unsafe-review`, coverage tools, network
access, or GitHub APIs for its own scan.

This release does not claim macro-expanded, type-aware, MIR-level, build-aware,
control-flow, data-flow, unsafe-proof, test-adequacy, or coverage-proof
analysis.
