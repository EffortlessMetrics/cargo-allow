# cargo-allow v0.2.0

> **Draft final candidate — not published on GitHub.**
> Final registry publication and closeout evidence remain `NotProven`.
> `0.1.11` is the stable rollback
> baseline; the public `0.2.0-rc.1` prerelease carries incident lineage.
> This draft does not authorize namespace publication, a `v0.2.0` tag, or
> public release finalization.

The final candidate targets Rust 1.95 and includes the structured
finding-to-receipt workflow and topology-derived release evidence. A source
build reporting `0.2.0` does not establish final-release qualification.

The [2026-08-24 RC incident record](https://github.com/EffortlessMetrics/cargo-allow/blob/main/docs/release/incidents/2026-08-24-rc1-tag-movement.md)
retains the public prerelease's install evidence and publication across
multiple source commits. RC.1 may inform pilot feedback, but its bytes,
freeze evidence, and authorization cannot be reused for the final release.
Its observed tag and incident history remain unchanged.
The 2026-10-10 GitHub readback reports that RC.1 record with
`prerelease=false` and as GitHub Latest. That provider state does not make
RC.1 the final `0.2.0` release or change the `0.1.11` rollback baseline.
No final `v0.2.0` tag or GitHub Release was observed; current registry
publication remains separately `NotProven`.

## Highlights

- **MSRV raised to Rust 1.95** — the stable `0.1.11` baseline uses Rust 1.85
- **`add --update`** — atomic in-place ledger mutation
- **`why` single-file fast path** — scoped diagnosis for one-finding questions;
  [dated benchmark evidence](https://github.com/EffortlessMetrics/cargo-allow/blob/main/docs/performance-budgets.md)
  records the host, build profile, and fixture limits
- **`why --plan` + `add --from-plan`** — structured finding-to-receipt handoff with targeted recheck
- **Operator guidance** — `check` remediation roadmap, `diff` why/add suggestions,
  `list` next-steps, and `doctor` repair hints; consistency and recovery
  qualification remain tracked below. Emitted `diff`/`worklist` schema coherence
  and full-ledger `explain` ambiguity reporting are delivered by
  [#4430](https://github.com/EffortlessMetrics/cargo-allow/pull/4430) and
  [#4431](https://github.com/EffortlessMetrics/cargo-allow/pull/4431)
- **Release evidence contract** — topology-derived `ReleaseManifestV2` with
  production Rust release-identity and publication reconciliation. The workflow
  preserves publication receipts through separate repackaging
  ([#4432](https://github.com/EffortlessMetrics/cargo-allow/pull/4432)); complete
  current publication and actual-asset evidence remain required
- **Command migration parity** — the older command-level corpus is complete;
  experimental three-product extraction remains `contract_only`, `Blocked`,
  and `OldPathStillReachable`. These are sibling-product cutover states, not
  cargo-allow release gates; selected shared dependencies still need exact
  qualification
- **Measured operator loop** — hosted Linux release-build latency and configured
  payload ceilings, with V4 receipts retaining binary identity, timings,
  digests, and artifact byte counts. Advisory targets remain separate from
  these enforced ceilings

  [#3150](https://github.com/EffortlessMetrics/cargo-allow/issues/3150);

## Install

Use this command only after crates.io publishes the exact `0.2.0` package and
the tag workflow's install smoke succeeds:

```bash
cargo install cargo-allow --version 0.2.0 --locked
```

## Claim Boundary

cargo-allow is a source-syntax policy linter and durable exception ledger.
Its scanner observes source-tree inventory without executing repository code.
It makes no compilation, type-analysis, macro-expansion, MIR, runtime,
unsafe-proof, or test-adequacy claim. Candidate platform/install observations
apply only to the exact bytes and environments qualified in the release record.
