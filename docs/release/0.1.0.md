# 0.1.0 Release Runbook

This runbook is for the first crates.io release of `cargo-allow`.

The release is irreversible once packages are published. If a published package
is wrong, the rollback path is to yank the affected version and publish a fixed
patch release. Do not publish from a dirty tree.

## Claim

The 0.1.0 release may claim:

```text
cargo-allow inventories syntax-visible source exceptions and checks them
against a policy ledger.
```

It must not claim macro-expanded, type-aware, MIR-level, build-aware,
control-flow, data-flow, unsafe-proof, test-adequacy, or coverage-proof
analysis.

## Preflight

Run from repository root on `main` after all release-prep PRs are merged:

```bash
git status --short --branch
git fetch --prune
git pull --ff-only
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo run -p cargo-allow -- allow check --mode no-new \
  --format markdown \
  --receipt target/cargo-allow/check.receipt.json \
  --output target/cargo-allow/check.md
cargo package --list --workspace
```

Expected cargo-allow posture before publication:

```text
44 matched, 0 new, 0 stale
```

## Publish Order

Publish internal crates in dependency order:

```text
1. allow-core
2. allow-policy
3. allow-inventory
4. allow-files
5. allow-rust
6. allow-match
7. allow-report
8. allow-diff
9. allow-policy-legacy
10. cargo-allow
```

This ordering matters because dependent crates use crates.io after publication.
A dependent crate's `cargo publish --dry-run` will not fully verify until its
internal registry dependencies are already published and visible in the index.

## Per-Crate Loop

For each crate in publish order:

```bash
cargo publish --dry-run -p <crate> --locked
cargo publish -p <crate> --locked
```

After each publish, wait for crates.io/index visibility before dry-running the
next dependent crate. Verify with:

```bash
cargo info <crate>
```

If crates.io visibility lags, wait and retry the next dry-run. Do not edit
manifests or broaden policy to force progress.

## Final Verification

After `cargo-allow` is published:

```bash
cargo info cargo-allow
cargo install cargo-allow --locked
cargo-allow --help
cargo-allow check --mode no-new
```

Record the final published versions, install command, and no-new posture in the
release closeout notes.

## Rollback

Crates.io versions are immutable. If publication is wrong:

```bash
cargo yank <crate> --version 0.1.0
```

Then prepare and publish a patch release. Do not reuse `0.1.0` for corrected
contents.
