# 0.2.0 Release Record

> **Status:** The workspace version on `main` is `0.2.0` but this version is
> **not yet published** to crates.io. The latest published release is `0.1.11`.
> Installing from `main` HEAD produces `cargo-allow 0.2.0`, which is a
> pre-release candidate. The version will publish when the release-blocker
> issues are closed and the candidate is requalified (#2501/#2502).

0.2.0 is the first release on Rust 1.95. It raises the MSRV, completes the
fast structured finding-to-receipt workflow, closes all migration-parity compat
lanes, and adds release provenance (ReleaseManifestV1 with keyless attestation).

## Operator value

```text
doctor / audit
→ why --kind ... --path ... --line ...
→ add --update (or add --from-plan)
→ check --mode no-new
→ list / explain / worklist
→ diff --base <base>
```

The finding-to-receipt loop is now fast, actionable, and honest at every step.

## Highlights

- MSRV raised from 1.85 to 1.95 (#2371)
- `add --update` / `migrate --update`: atomic in-place ledger mutation
- `why` single-file fast path (73x faster than full audit)
- `why --plan` + `add --from-plan`: structured finding-to-receipt handoff
- Targeted recheck after `add --from-plan` writes the entry
- `check` remediation roadmap, `diff` why/add suggestions, `list` next-steps,
  `doctor` repair hints
- `ReleaseManifestV1` schema + generator + keyless OIDC attestation with
  typed `Complete`/`Incomplete` validation gate (#2279/#2280/#2495/#2497)
- SHA-pinned GitHub Actions + OIDC fail-closed (#1896/#2281)
- Atomicity: canonical lock keys + containment on all 7 mutation commands (#2487/#2490)
- Scanner completeness: fail-closed on skipped tracked Rust files (#2486/#2493)
- Versioned scanner capability contract: `cargo-allow capabilities --format json`
  emits `cargo-allow.sensor-capabilities.v1` generation 1 for the source
  candidate; it remains source-tree-only and makes no compilation, type,
  macro, MIR, runtime, or test-adequacy claim (#2570)
- Incremental scan cache architecture (#2514)
- All 11 migration-parity compat lanes at `complete`
- `Selector.line_hint` propagation retired; `maybe_line_distance_score` removed
- Performance budget suite with measured baseline
- Product language corrected: "source-syntax policy linter and exception ledger"

## Non-Goals

- This release does not claim macro-expanded, type-aware, MIR-level,
  build-aware, control-flow, data-flow, unsafe-proof, test-adequacy, or
  coverage-proof behavior.
- Full import mode (#1466) and external ripr adoption remain blocked on
  explicit adoption requests.
- Non-Rust semantic sensors (workflow YAML, TOML, shell parsing) are future
  work.

## Scanner capability contract

The 0.2.0 source candidate exposes the checked sensor catalog through the
installed binary:

```bash
cargo-allow capabilities --format json
```

The JSON contract is `cargo-allow.sensor-capabilities.v1`, generation 1. It
describes the source-tree sensors, their supported and excluded claims, and
their limitations. It is a discovery and claim-boundary surface, not a
release-publication or semantic-analysis guarantee. In particular, the
catalog does not claim compilation, type analysis, macro expansion, MIR,
runtime behavior, or test adequacy. The catalog and support metadata are
tracked by [#2570](https://github.com/EffortlessMetrics/cargo-allow/issues/2570)
and [docs/support-matrix.toml](../support-matrix.toml).

## Known Limitations

- Source-tree/source-syntax scan only; cargo-allow does not execute repository
  code or invoke Cargo, rustc, Clippy, build scripts, or proc macros.
- Performance budgets are measured but not yet gated in CI.
- `why` fast path is advisory; `add` keeps the full pipeline.
- `dtolnay/rust-toolchain` uses branch refs (not tags); SHA-pinning its
  branch would break on the next toolchain release. Documented as a known
  supply-chain limitation (#2498).
- Manifest generation uses shell assembly (`generate-release-manifest.sh`);
  typed Rust generation exists (#2549) but is not yet wired into the workflow
  as the authoritative path (#2497 follow-up for 0.3.0).

## Rollback

```bash
cargo yank <crate> --version 0.2.0
```

Do not reuse `0.2.0` for corrected contents.
