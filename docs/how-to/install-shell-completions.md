# Install shell completions

Use this guide to install completions generated by the exact `cargo-allow`
binary you intend to run. The generator reads the binary's Clap command graph,
so regenerate the file after upgrading cargo-allow.

These scripts only define command-line completions. They do not scan the
current repository, execute repository code, contact the network, or mutate
policy. The generated command is for `cargo-allow`; Cargo owns completion for
the `cargo allow` compatibility invocation.

## Bash

```bash
completion_dir="${XDG_DATA_HOME:-$HOME/.local/share}/bash-completion/completions"
mkdir -p "$completion_dir"
cargo-allow completions bash > "$completion_dir/cargo-allow"
```

Start a new shell, or source the generated file if your Bash completion setup
loads files from that directory. To remove it:

```bash
rm -f "${XDG_DATA_HOME:-$HOME/.local/share}/bash-completion/completions/cargo-allow"
```

## Zsh

Create a completion directory, add it to `fpath` before `compinit`, and
generate the `_cargo-allow` file:

```zsh
mkdir -p ~/.zfunc
cargo-allow completions zsh > ~/.zfunc/_cargo-allow
```

Add this once to `~/.zshrc` before the first `compinit` call:

```zsh
fpath=(~/.zfunc $fpath)
autoload -U compinit && compinit
```

Restart Zsh, or run `exec zsh`. To remove the completion, delete
`~/.zfunc/_cargo-allow` and remove the corresponding `fpath` line if it is no
longer used by another completion.

## Fish

```fish
mkdir -p ~/.config/fish/completions
cargo-allow completions fish > ~/.config/fish/completions/cargo-allow.fish
```

Fish loads the file in new shells. Remove it with:

```fish
rm -f ~/.config/fish/completions/cargo-allow.fish
```

## PowerShell

Keep the generated script separate from the profile so it can be replaced or
removed without editing generated code. Run this in the PowerShell version
that owns the profile you use:

```powershell
$completionDir = Join-Path $HOME '.cargo-allow'
$completionPath = Join-Path $completionDir 'cargo-allow-completions.ps1'
New-Item -ItemType Directory -Force -Path $completionDir | Out-Null
cargo-allow completions powershell | Set-Content -Path $completionPath -Encoding utf8
```

Add this one dot-source line to `$PROFILE`:

```powershell
. "$HOME\.cargo-allow\cargo-allow-completions.ps1"
```

Restart PowerShell, or dot-source the generated file once in the current
session. To remove the completion, remove the dot-source line from `$PROFILE`
and delete `$HOME\.cargo-allow\cargo-allow-completions.ps1`.

## Elvish

```elvish
mkdir -p ~/.config/elvish/lib
cargo-allow completions elvish > ~/.config/elvish/lib/cargo-allow.elv
```

Add this once to the Elvish `rc.elv` file:

```elvish
use cargo-allow
```

Restart Elvish to load the module. To remove the completion, delete
`~/.config/elvish/lib/cargo-allow.elv` and remove the `use cargo-allow` line.

## Source checkouts and upgrades

When using an unpublished checkout, replace `cargo-allow` in the commands
above with `cargo run -p cargo-allow --`, for example:

```bash
cargo run -p cargo-allow -- completions bash > ~/.local/share/bash-completion/completions/cargo-allow
```

Regenerate after every binary upgrade. The generated file belongs to the
binary that produced it; do not copy a completion script from a different
version and treat it as version-matched.

This guide covers the currently shipped completion command. Generated
command references are available from the same installed binary:

```bash
cargo-allow reference > cargo-allow-command-reference.md
cargo-allow reference --format json > cargo-allow-command-reference.json
```

From a source checkout, use the same installed-binary path through Cargo:

```bash
cargo run -p cargo-allow -- reference > cargo-allow-command-reference.md
cargo run -p cargo-allow -- reference --format json > cargo-allow-command-reference.json
```

These references are generated from the exact Clap graph of the binary. They
describe command grammar, options, defaults, and value choices; support
channels, mutation posture, and release packaging remain separate contracts
under issue #2479. Regenerate after every binary upgrade.

Generated manpages and release-archive packaging remain separate follow-up
work under issue #2479.
