## 5. Pilot Handoff Packets

The following is prepared scope, not permission to open a target PR. First record
repository/maintainer, exact refreshed commit/tree, subject identity, platform,
allowed files, policy-review owner and advisory/blocking choice on #3150.

| Surface | Clean audit candidate: env-check | Deferred brownfield: adze |
| --- | --- | --- |
| First action | Read-only exact installed audit; decide class before bootstrap. | Read-only exact installed audit plus legacy-policy mapping. |
| Proposed adoption files | `policy/allow.toml`, one `.github/workflows/cargo-allow.yml`, one short operator/rollback note. | Same bounded additions; edit existing legacy policy only if separately included in consent. |
| Policy route | No manufactured baseline; repair bounded findings or reject clean classification. | Reviewed owner/reason/evidence/selector decisions; generated baseline remains debt. |
| Repair candidate | Replace panic-shaped schema fixture setup in CLI tests with fallible setup, if authorized and within the final measured scope. | Narrow a runtime lint suppression or one non-Rust scope after checking its actual findings and coverage; never translate an entire quarantine into approval. |
| CI posture | No workflow until audit acceptance; blocking pilot job only with explicit consent. | Advisory until reviewed baseline acceptance and explicit blocking decision. |
| Negative control | After adoption authorization, temporary tracked Rust fixture containing a selected blocking construct; retain a failing check, remove fixture and prove recovery. | Same unreceipted-finding control plus prove a narrowed/pruned entry changes the expected posture. |
| Rollback | Restore exact preimages of only the adopted policy/workflow/note and temporary control. | Same; preserve legacy ledgers, generated/vendor content and unrelated work. |

Before execution, verify command/flag support from the exact installed binary's
help. The intended sequence is `audit`, inspect `worklist`/`why`, review any
proposed policy edits, `check --mode no-new`, and `diff --base <recorded-base>`.
Use an absolute executable path, exact base and explicit output/receipt paths.
Do not blindly reuse source-candidate command syntax against the historical RC.
Retain bounded outputs under `target/cargo-allow/pilot/`: installation identity,
audit, reviewed plan, check receipt, diff, negative-control red/recovery results
and an `EvaluationArtifactSetV1` reference where supported by the chosen subject.
Do not invent an artifact schema or claim it was emitted when it was not.

Capture time/commands to first useful result, policy discovery source, durable
file count, default sensor families, proposed blocking/advisory/opt-in posture,
generated versus reviewed row counts and any selected profile comparison. These
measurements are **NotRun**, including the earlier #3884 comparison request.
No `.allow/config.toml`, optional profile, cargo-intent, cargo-proof, compiler or
project execution is a prerequisite for the ordinary source-tree scan.

A proposed GitHub Actions scan needs read-only repository access (`contents: read`)
and bounded artifact upload, with no secrets, write token or ruleset mutation.
Pin the chosen installation/toolchain and checkout enough history for the exact
base comparison. Scan job results must be distinguishable from unrelated target
build failures. Public source does not authorize uploading private paths, raw
source dumps, secret material or unbounded logs. Route reproducible product
friction to #3151 and package-changing defects back to the exact-candidate rail;
invalidate affected installed receipts after candidate changes.

See [rollback ownership](../how-to/rollback-cargo-allow-adoption.md). Preserve
historical receipts and unrelated user work when removing pilot-owned artifacts.

## 7. Validation and Rejection Controls

**Pass:** six real public repositories compared at exact complete trees; selected
manifests, policies, source and CI job outcomes inspected. **Not run:** cargo-allow
scans, installation, candidate builds/tests, target PRs, workflow changes, profile
burden measurement and installed pilots. CI observations above belong to the

created by broad baselining or test exclusion; reject a brownfield subject with
no actual judgment/repair opportunity. Reject ambient/source/floating binaries,
RC-as-final identity, generated/private-scope blindness and unexplained red CI
as evidence of product strength. Distinct source classes, exact subject identity,
explicit consent and red/recovery controls must survive the eventual execution.

This packet repairs selection source truth. It does not close #2466/#2467,
qualify final 0.2.0, or authorize target adoption, release or live settings changes.
