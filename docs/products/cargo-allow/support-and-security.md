# cargo-allow issue routing and security ownership

Use the repository's GitHub issue tracker for reproducible product bugs,
documentation drift, policy questions, and feature requests. Include the
command, exact version or commit, operating system, minimal fixture, receipt or
diagnostic output, and the claim you expected the tool to make.

For suspected security vulnerabilities, avoid public disclosure of exploitable
details. Use the repository's private security reporting channel exposed by
GitHub, then provide a minimal reproduction through the maintainers' requested
secure path. Do not attach credentials, registry tokens, or private source to
an issue or receipt.

The cargo-allow maintainers own the source-tree ledger and scanner contracts.
External proof, release, and hosting systems own their own evidence; a
cargo-allow report does not transfer that ownership.

Claim boundary: routing guidance is not a response-time, remediation, or
release-readiness guarantee.
