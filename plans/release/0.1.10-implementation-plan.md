# Implementation Plan: Adoption-Trust Release 0.1.10

## Purpose

Sequence release automation proof and the `0.1.10` cut without staging version
bumps too early.

## Non-Goals

- No `0.2.0` cut.
- No version bump until PR E3 authorization.
- No tag push until PR E4 authorization.

## PR Sequence (E1–E5)

### PR E1 — Document automated release prerequisites

Purpose: make Trusted Publishing, token fallback, dry-run, publish order, and
recovery steps operationally clear.

Files: `docs/release/README.md`, `docs/ci.md` (if needed).

Validation: doc review; link check via spec-system when registered.

Claim boundary: operator documentation only.

Tag/version/release-artifact preflight (first `0.1.10` automation gap) lands
separately on `release/tag-version-preflight` via
`scripts/release-version-preflight.sh` wired into the publish job.

### PR E2 — Dry-run release workflow on main

Purpose: produce workflow_dispatch evidence without crates.io upload.

Files: release record notes, optional `docs/release/0.1.10.md` prereq section.

Validation: green workflow run id recorded.

Claim boundary: dry-run proof only; not a publish.

### PR E3 — Stage 0.1.10 when ready

Purpose: version bump, CHANGELOG section, `docs/release/0.1.10.md`,
`docs/release/github/v0.1.10.md`.

Non-goals: no tag until E4 authorization.

Validation: fmt, clippy, test, package, no-new guard.

Claim boundary: release prep only.

### PR E4 — Tag v0.1.10 after approval

Purpose: push annotated tag to trigger [release.yml](../../.github/workflows/release.yml).

Requires: explicit release authorization, E1–E3 complete, Trusted Publishing ready.

Claim boundary: triggers real publish.

### PR E5 — Record automated release evidence

Purpose: finalize release closeout with workflow run, registry checks, install-smoke.

Files: `docs/release/0.1.10.md` final sections.

Claim boundary: records publish evidence; does not prove external adoption.
