# cargo-allow Examples

These examples show common source-tree exception governance patterns. They are
copyable starting points, not universal policy defaults.

The examples keep the core claim boundary intact: `cargo-allow` scans
source-tree/source syntax and policy files. Evidence references can point to
other tools, but `cargo-allow` does not execute those tools during its own scan.

## No-New Adoption

Use no-new mode when adopting cargo-allow without fixing every historical
finding first:

```bash
cargo-allow audit --format human
cargo-allow propose --write policy/allow.proposed.toml
cargo-allow check --mode no-new
```

Generated proposal entries should stay visibly temporary:

```toml
owner = "unowned"
classification = "baseline_debt"
reason = "Generated by cargo-allow propose; requires human review."
expires = "2026-08-01"
```

Do not turn generated baseline debt into permanent approval just to make CI
quiet.

## Strict Source-Tree Check

A stricter repository should require ownership, rationale, classification, and
lifecycle metadata:

```toml
[requirements]
owner_required = true
reason_required = true
classification_required = true
expires_or_review_after_required = true
allow_bare_allow_attributes = false
stale_entries_fail = true

[requirements.unsafe]
evidence_required = true
verified_evidence_required = true
safety_comment_required = false
```

Then run:

```bash
cargo-allow check --mode strict
```

## Non-Rust File Receipt

Use exact file scopes for operational files where practical:

```toml
[[allow]]
id = "allow-ci-0001"
kind = "non_rust_file"
family = "ci_declarative"
path = ".github/workflows/release.yml"
owner = "release"
classification = "release_automation"
reason = "Runs the release validation lane from reviewed workflow steps."
created = "2026-05-27"
review_after = "2026-11-01"
evidence = ["doc:docs/release/README.md"]

[allow.selector]
ast_kind = "tracked_file"
glob = ".github/workflows/release.yml"
symbol = ".github/workflows/release.yml"
target_fingerprint = "yml"
```

## Panic-Family Receipt

Prefer structural selector fields over line-only matching:

```toml
[[allow]]
id = "allow-panic-0001"
kind = "panic"
family = "indexing_slicing"
path = "crates/parser/src/span.rs"
owner = "parser"
classification = "validated_span_invariant"
reason = "The parser validates the text range before slicing."
created = "2026-05-27"
review_after = "2026-08-01"
evidence = [
  "test:parser_rejects_invalid_text_range",
  "doc:docs/specs/parser-span-invariants.md",
]

[allow.selector]
ast_kind = "index_expr"
container = "slice_checked_text_range"
symbol = "source[range]"
normalized_snippet_hash = "fnv1a64:..."
```

## Unsafe Receipt

Unsafe exceptions should carry stronger evidence than ordinary source-policy
exceptions:

```toml
[[allow]]
id = "allow-unsafe-0001"
kind = "unsafe"
family = "unsafe_block"
path = "crates/runtime/src/ffi.rs"
owner = "runtime"
classification = "ffi_boundary"
reason = "The unsafe block is the narrow boundary around a checked foreign pointer read."
created = "2026-05-27"
review_after = "2026-08-01"
evidence = [
  "unsafe-review:docs/evidence/unsafe-review/ffi-read-buffer.json",
  "test:ffi_read_buffer_rejects_null_pointer",
  "doc:docs/safety/ffi-read-buffer.md",
]

[allow.selector]
ast_kind = "unsafe_block"
container = "read_buffer"
normalized_snippet_hash = "fnv1a64:..."
```

`cargo-allow` validates local evidence paths when they are used in real policy,
but it does not interpret the referenced receipts as proof.

## Lint Suppression Receipt

For source suppressions, link the source attribute back to the ledger entry:

```rust
#[expect(
    clippy::indexing_slicing,
    reason = "policy:allow-panic-0001: parser validates the range before slicing"
)]
fn slice_checked_text_range(source: &str, range: std::ops::Range<usize>) -> &str {
    &source[range]
}
```

The policy entry should cover the same path/container/lint surface and carry the
human reason and lifecycle.

## PR Posture Summary

Use the GitHub Actions examples for CI wiring (copy these files; do not invent
checkout/install/artifact steps):

- [PR posture diff](github-actions/cargo-allow-diff.yml) — requires `fetch-depth: 0`
- [Mainline no-new check](github-actions/cargo-allow-check.yml)

Operator how-to: [Run in CI](../docs/how-to/run-in-ci.md).
Troubleshooting: [Troubleshoot cargo-allow](../docs/how-to/troubleshoot-cargo-allow.md).
Rollback: [Rollback cargo-allow adoption](../docs/how-to/rollback-cargo-allow-adoption.md).

The PR lane should publish a Markdown summary:

```bash
cargo-allow diff --base origin/main \
  --format markdown \
  --output target/cargo-allow/pr-summary.md
```

The mainline lane should publish the full local artifact set under
`target/cargo-allow/`:

```bash
cargo-allow audit --format json --output target/cargo-allow/audit.json
cargo-allow audit --format html --output target/cargo-allow/audit.html
cargo-allow check --mode no-new \
  --format markdown \
  --receipt target/cargo-allow/check.receipt.json \
  --output target/cargo-allow/check.md
cargo-allow check --mode no-new \
  --format sarif \
  --output target/cargo-allow/check.sarif
```

## Agent Worklist

Use worklists to route cleanup work without asking agents to invent scope:

```bash
cargo-allow worklist \
  --format json \
  --output target/cargo-allow/worklist.json
```

Work items are suggestions for humans or authorized agents. They should fix,
prove, narrow, or remove exceptions instead of adding suppressions just to make
the report pass.
